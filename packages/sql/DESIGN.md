# How a schema dump is read

`readSqlSchema` reads the tables a dump of the database declares, such as Rails' `db/structure.sql` or what `pg_dump --schema-only` writes. The [README](./README.md) explains what the package is for.

```ts
readSqlSchema(`
CREATE TABLE public.orders (
    id bigint NOT NULL,
    status character varying DEFAULT 'pending'::character varying NOT NULL
);
ALTER TABLE ONLY public.orders ALTER COLUMN id SET DEFAULT nextval('public.orders_id_seq'::regclass);
ALTER TABLE ONLY public.orders ADD CONSTRAINT orders_pkey PRIMARY KEY (id);
`);
// { tables: [{ name: "orders", line: 2, columns: [
//     { name: "id", type: "bigint", nullable: false, default: true, primary: true },
//     { name: "status", type: "character varying", nullable: false, default: true } ] }],
//   unread: [], statements: 3 }
```

Each column comes back with the fields a storage contract gives a column, so a contract reader can pass them on as they are.

## Which statements count

The dump is split into statements at each `;` written in code, so a `;` inside a literal, a comment or a function's dollar-quoted body does not end one. Only two kinds are read. `CREATE TABLE` gives the columns. pg_dump writes the keys and a serial column's default after the tables, so `ALTER TABLE` is read too: `ADD CONSTRAINT` for a primary or foreign key, and `ALTER COLUMN ... SET DEFAULT` or `DROP DEFAULT`. Every other statement, such as an index, a function or a trigger, is skipped.

A table in the `public` schema is named without it, and a table in any other schema keeps it, as `audit.events`. `CREATE TYPE ... AS ENUM` gives the enum types, and a column of one has the type `enum`.

## A type the grammar does not know

The grammar knows only the built-in types, and a dump is full of others: enum types, and types from extensions such as `citext` or `halfvec`. When the grammar rejects a table, each definition is parsed on its own. When it rejects a column, the column is parsed again with `text` in place of its type and of any cast in its default, which is enough to read its nullability and whether it has a default. The type is then taken as written, without its schema or length.

A column that fails even then keeps its name and type, and its nullability and default are left unstated. A partition of another table lists no columns, so it is left out. An `ALTER TABLE` the grammar rejects is skipped, and when it is an `ALTER COLUMN`, that column's default is left unstated as well, since the statement may have given it one, as `ADD GENERATED BY DEFAULT AS IDENTITY` does.

## How much was read

Whatever was not read is listed in `unread`, with its line, its table and its column where it has one. `statements` counts every `CREATE TABLE` and `ALTER TABLE` in the dump, read or not. Together they say how much of the dump was read.

A MySQL dump is read with `{ dialect: "mysql" }`. There `AUTO_INCREMENT` counts as a default, `DEFAULT NULL` does not, and `tinyint(1)` keeps its width, since MySQL spells a boolean that way.
