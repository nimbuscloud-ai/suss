# declaration-positions-ruby

One graphql-ruby type per file, each declaring one field named `value`,
each differing only in where the `field` call is written inside the class
body.

Ruby runs a class body like any other code, so a `field` call can go
anywhere a statement can go: inside an `if`, inside a `.each` block,
inside a `begin`, inside a `class_eval`. A reader that takes the body's
own statement list finds the first row and loses the rest without saying
anything.

This is the Ruby member of a set. `subject-positions` is the TypeScript
matrix and `subject-positions-python` is the Python one. Those two ask
which expression is the app, because a route hangs on an object. Ruby
recognizes a type by what its class inherits, so there is no object to
identify and the question here is only where the declaration is written.

Four rows are here to pin what suss cannot read, and each one says why in
its own file: a field name computed from a loop variable, a resolver
defined with `define_method`, a field declared in an included module, and
a field declared on a class named by a variable.
